> 一定有恒成立不等式：(Loop Invariant 不等式)
>
> [i ... left-1]  <= pivot
> [right+1 ... j] >= pivot

更准确地说，空隙情况不确定，可以分为：

循环结束时，未处理区间 [left, right] 可能缩成

1. **一个点**
2. **也可能缩成空区间**

对应两种情况如下：

1. **若 left == right，未处理区间是一个点；**
2. **若 left == right + 1，未处理区间为空；**

所以分两种情况，本质是在讨论：待处理区最终是单点还是空集，而不是单纯在讨论 left-1 和 right+1 的空隙。

下面具体分析这两种末态情况：

**1 left == right (巧合恰好相遇)**  

此时left right共同指向的元素，我们称之为***flag***；

那么根据推广的***loop invariant***：必然有 

left左侧的元素 <= pivot  && right右侧的元素 >= pivot

又因为 left 和 right 此时恰好指向同一个位置

那么flag左侧的元素都 <= pivot，右侧 >= pivot，**完成分区**，只需要分治继续对[i, right]和[right+1, j]进行重复的子问题操作即可！

**下面会引出一个子问题**：我们当前指向的**flag元素是什么样子的？**需要参与接下来的进一步排序么？

很显然因为在当前状态下：

nums[right] <= pivot (结束循环时，right应该指向一个自己想要找的元素位置)；

同理nums[left] >= pivot

flag <= pivot  且  flag >= pivot  所以 flag == pivot恒成立！

位置已经正确！

这里需要注意一下，由于我们在本轮函数调用过程中由于内层循环的限制：能够推出当前公共指针指向的元素必然等于pivot值。那么，在下一次的分治函数的调用过程中，想要让这个pivot的值参与元素交换并改变位置，就只有一种可能性：**就是下一轮分治函数中选择的pivot的值等于这个flag值**。

为什么？ 根据上面的数据推导，我们可以知道flag元素所对应的值必然是左边所有元素里最大的一个。又因为在下一轮函数调用的过程中想要让right指针指向这个flag元素，必然要保证flag元素 <= pivot （新的pivot）  又因为flag是最大值，所以只能是 == 这种情况。因此在涉及 flag元素的不稳定交换频繁时，原数组中重复元素的个数应该比较多。

**2 left == right+1 (很多情况下)**  

此时left 和 right不在指向同一个元素；而是指向一组数字我们称之为nums[L], nums[R]；我们将这个数对看成一个整体，不难看出【**nums[right], nums[left]**】左侧的元素必然全<=pivot，右侧的元素必然全>=pivot；

又因为在当前状态下：nums[right] <= pivot (结束循环时，right应该指向一个自己想要找的元素位置)；

同理nums[left] >= pivot

所以有 nums[right] <= pivot <= nums[left]，那么我们可以轻松的将整个数组划分为两个部分，满足我们开辟当前函数栈帧的需求（将原问题划分为两个不互相干涉的无重复的子问题并继续求解！）

即将nums数组划分为nums[i --- right] 和 nums[right + 1, j];
